为什么用 TaskSSH

单文件、无依赖，将批量操作编写为可复用的流程

⚙️

任务编排

将一个或多个操作组合为有序流程。命令执行、上传、下载可自由组合，由单条命令触发执行。

📄

配置即文档

完整流程写入 inventory.yaml，可提交、可审查，便于团队理解发布流程。

🧩

原子能力

内建 command / push / fetch 三种 action，可独立使用，亦可组合为流程。

🔀

变量替换

三层变量（全局 / 组 / 主机）配合严格模式。同一配置适配多套环境，未解析变量将直接报错。

🛡️

严格模式

未解析的变量直接报错，避免命令作用于非预期路径。

⚡

并发执行

通过 -c 指定并发数，日志按主机缓冲，避免交错输出。

快速开始

下载、定义清单、执行任务

1

下载

从 GitHub Releases 下载对应平台的二进制，或通过 go build -o taskssh main.go 从源码构建。

2

定义清单

创建 inventory.yaml，声明服务器组、主机及任务步骤。

3

执行任务

运行 taskssh release prod -y，按清单定义完成整个流程。

示例：发布流程

tasks:
  release:
    steps:
      - name: "上传新版本"
        action: push
        with:
          file: "./dist/${app_name}-${version}.jar"
          dest: "${service_path}"
          force: true
          backup: true
      - name: "重启服务"
        action: command
        with:
          command: "systemctl restart ${app_name}"
        delay: 5
      - name: "健康检查"
        action: command
        with:
          command: "curl -sf http://localhost:8080/health"

执行：taskssh release prod-trans -i inventory.yaml -y

内置任务

三种原子 Action，覆盖常规批量运维场景

command

执行远程命令

taskssh command prod -e "ls -la /opt"

push

上传文件至远程主机

taskssh push prod -f app.jar -d /opt/app/

fetch

从远程主机下载文件

taskssh fetch prod -f /var/log/app.log -d ./logs/
